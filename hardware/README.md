# 실물 연결·회전 방향 확인

ID 1–17은 [모터 ID 표](../docs/motor_ids.md)에 대응하며, 결과는
`config/hardware.yaml`에 저장합니다. 기존 Biped의 SDK Protocol 2.0/OpenCR
접속 방식을 참고한 독립 점검 도구입니다. 변신 궤적은 실행하지 않습니다.
방향과 영점은 처음에 미확인(null)이며, 기존 로봇 값을 복사하지 않았습니다.
그리퍼 17번은 현재 URDF에 대응 관절이 없습니다.

```bash
cd /home/dongwoo/biped_bike_ws
source /opt/ros/jazzy/setup.bash
# 읽기 전용: 1–17번 모델, 모드, 토크, 위치, 오류, 전압, 온도
python3 src/shift_ostrich/hardware/calibrate.py --port /dev/ttyACM0
# 현재 위치 유지와 개별 방향 시험
python3 src/shift_ostrich/hardware/calibrate.py --port /dev/ttyACM0 --interactive
```

OpenCR USB·모터 전원을 연결하고 다른 모터 제어 프로그램과 Wizard를 종료합니다.
로봇은 받침대나 손으로 지지합니다. 이 도구는 다른 종류의 프로그램의 포트 점유를
차단하지 않으므로 동시에 실행하지 않습니다.

대화형 명령:

- `status`: 읽기 전용 점검.
- `prepare`: 토크 OFF·정상 응답을 확인하고 바퀴 6/12번은 속도 모드 1,
  나머지는 위치 모드 3으로 맞춥니다. 변경 전 상태는 `hardware/logs/`에 저장합니다.
- `hold`: 현재 위치를 목표로 기록한 뒤 위치 관절의 토크를 켭니다.
  바퀴 6/12번에는 쓰지 않습니다. 기존 모드·게인·PWM 설정은 유지합니다.
  모든 위치 관절의 정상 응답, 토크 OFF, 위치 모드 3과 모델별 전압을 먼저 확인합니다.
  goal 명령으로 자동 토크가 켜지는 설정은 차단합니다.
- `hold-body`: `hold`와 같지만 그리퍼 17번도 제외합니다.
- `jog 1 2`: 1번 모터의 엔코더 양의 방향으로 2° 시험. `jog 1 -2`는 반대.
  명령 1회 최대 2°, 시작 위치에서 누적 최대 약 5°, 목표 이동 속도 최대 2°/s입니다.
  기계적 간섭·각도 한계는 사람이 관찰해야 합니다. 바퀴 시험은 제외합니다.
  시간 기반 프로파일인 관절은 토크 유지까지만 허용하며 jog는 차단합니다.
- `direction 1 1`: 엔코더 양의 방향과 URDF 관절 양의 방향이 같으면 +1 기록.
  반대면 `direction 1 -1`. 모터의 Drive Mode는 바꾸지 않습니다.
- `off`: 이 도구가 켠 모터 토크 OFF. 지지한 상태에서 실행합니다.
- `quit` / Ctrl+C: 이 도구가 켠 모터의 토크 OFF를 시도하고 종료합니다.

`urdf_axis`는 관절 로컬 좌표계에서 오른손 법칙을 따르는 양의 회전축입니다.
좌우 대칭 관절도 URDF 축 부호가 다를 수 있으므로 각각 확인합니다.
`center_tick`은 URDF 0°에 해당하는 실제 엔코더 값이며 **현재 자세를 0°로 간주하지 않습니다.**
방향 확인이 끝나도 영점을 별도 측정하기 전에는 저장된 변신 각도를 실물에 적용하지 않습니다.

현재 지원 제어표는 XL430-W250, XM430-W210, XM430-W350, XL330-M288입니다.
XL330-M288의 입력 전압은 3.7–6.0V 범위여야 토크를 켭니다.
제어표·전압 근거: [ROBOTIS XL330-M288 설명서](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/).
다른 모델은 ping 결과를 출력하고 레지스터 접근·토크를 차단합니다.
통신 오류가 나면 종료하며 이미 켠 모터의 토크 OFF를 시도합니다.
USB 단절 시에는 OFF 명령도 전달되지 않을 수 있습니다.
